# Optional read-orientation and contamination filtering

Two independent INI sections control the inputs to GATK FilterMutectCalls. Omitting either section leaves that option disabled and preserves the earlier analysis settings. Each section accepts `mode = off`, `auto` or `provided`. Supplying paths with `off`, mixing automatic/provided inputs, or omitting required paths is an error.

## Generate both models automatically

In either shipped INI template, edit the existing sections as shown below. For an older INI, add the sections once. Replace the example path with your own VCF.

```ini
[orientation]
mode = auto

[contamination]
mode = auto
sites = /references/common_biallelic_GRCh38.vcf.gz
```

The supplied common-SNP VCF requires an adjacent `.tbi`, population `INFO/AF`, sites-only biallelic SNPs with `0.01 <= AF <= 0.20`, and matching reference sequences/contig lengths. This is a separate resource from the PoN and the matched-normal BAM. Population AF is not the tumor variant allele fraction. BRISANCE validates REF, records, ordering, duplicate alleles and indexed count before using the resource. It does not download or silently rewrite it. Different alternate alleles at the same position remain distinct records.

Orientation `auto` requests `--mutect-f1r2-tar-gz` during the fresh Parabricks MutectCaller execution. GATK LearnReadOrientationModel converts those counts to orientation-artifact priors. This models artifacts associated with read orientation; it is not an indel-orientation correction. The caller's F1R2 output and the resulting priors are retained. Missing requested counts/model is a failure, with no fallback to filtering without the requested model.

Contamination `auto` runs GetPileupSummaries separately for the tumor and matched-normal BAMs, then CalculateContamination with `--matched-normal`, producing the tumor-specific contamination table and minor-allele-fraction segmentation. Both are supplied to FilterMutectCalls along with the raw called VCF and its Mutect stats. These are cross-sample contamination estimates, not a tumor-purity report.

The tools remain Parabricks 4.5.1-1 and GATK 4.6.2.0. Model estimation uses the `[filtering]` CPU, memory and Java heap limits. These added GATK stages are CPU tasks; the selected calling GPU is used by the caller and applicable PoN/QC utilities. Single-task execution remains enforced. Allow for the additional BAM reads, F1R2 storage and CPU time when planning the run.

## Supply existing per-sample models

```ini
[orientation]
mode = provided
priors = /models/P01_TUMOR.orientation_priors.tar.gz

[contamination]
mode = provided
table = /models/P01_TUMOR.contamination.table
segments = /models/P01_TUMOR.segments.table
```

`priors` must be the archive produced by LearnReadOrientationModel, not the F1R2-count archive. `table` is required; `segments` is optional for provided contamination. BRISANCE checks GATK table/archive structure, finite fractions, segmentation coordinates against the reference, and tumor sample identity. The priors must include the tumor sample configured in the INI. GATK priors archives may also contain another sample's priors, as generated by paired calling. Archives are inspected without extracting files.

These checks do not establish that supplied models came from the same library, BAM processing or calling run. The user must provide suitable models from the intended analysis. Do not reuse another patient's contamination estimate or transfer a historical estimate across changed BAM processing/reference builds without justification.

With `provided`, BRISANCE passes the checked files directly to FilterMutectCalls and skips the corresponding estimator. To use just one filter, set its section to `auto` or `provided` and leave the other at `off`.

## Existing BAMs and reports

Use `[analysis] input_mode = bam` with one tumor and one matched-normal BAM/index. The BAMs must already have the intended alignment, duplicate marking and recalibration; BAM mode does not redo those steps. A fresh analysis folder is required. Existing BAMs and resources are read-only; no automatic cleanup, overwrite or restart is introduced.

Outputs are published under `results/somatic_models/`, with F1R2 counts alongside the stage5 calls. The stage6 filter configuration records the actual model paths supplied. Completion requires all expected successful tasks and validates the model tables/priors, retaining their hashes in `completion.json`. QC metrics and PoN remain independent options. BAM QC already collected for unchanged BAMs need not be recomputed merely to enable these filters.

More filtering does not by itself demonstrate improved accuracy. Compare called alleles and filter reasons, then apply the same annotation/selection criteria across runs. The external harmonized exonic oncoplot procedure is not part of BRISANCE's native final-VCF selection.

## Check and launch

Choose a fresh analysis folder and verify the settings before starting the run.

```bash
bash interface/run_brisance.sh analysis.local.ini --check
bash interface/run_brisance.sh analysis.local.ini --run
```

## Release evidence

A GRCh38 WGS pilot completed five matched tumor–normal pairs from existing BAMs using a prepared PoN and both automatic modes. Each pair produced a final VEP-annotated PASS VCF with positive TLOD. This demonstrates end-to-end execution for that configuration. Other mode combinations are covered by software tests with simulated scientific tools. Sensitivity and specificity for these filters were not measured in the pilot.
